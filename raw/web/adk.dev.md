## Landing page — https://adk.dev/

# Build production agents, not prototypes.

ADK is the open-source agent development framework that lets you build, debug, and deploy reliable AI agents at enterprise scale. Available in Python, TypeScript, Go, Java, and Kotlin.

Install: `pip install google-adk` | `npm install @google/adk` | `go get google.golang.org/adk` | `com.google.adk:google-adk` | `com.google.adk:google-adk-kotlin-core`

**ADK Python 2.0 GA** with graph workflows and collaborative agents; ADK Kotlin also announced.

### Platform pillars (homepage)
- **Agents CLI** — build agents with agents; scaffold, test, evaluate, deploy
- **Graph Workflows** (ADK 2.0) — deterministic code + adaptive AI reasoning via graph-based architectures
- **Framework** — prompts → multi-agent orchestration → evaluation → enterprise deployment
- **Ecosystem** — open integrations with models, apps, data, resilience, eval partners

### FAQ highlights
- **Vibe coding:** ADK designed for humans and AI; connect coding assistant to ADK developer Skills
- **Models:** Model-agnostic — Gemini, Claude, Ollama, vLLM, LiteLLM, Agent Platform hosted, Apigee AI Gateway, etc.
- **Context management:** Treats context like source code — filters irrelevant events, summarizes turns, lazy-loads artifacts, tracks tokens
- **Deploy anywhere:** Containerize on own infra or one-command GCP deploy (Agent Runtime, Cloud Run, GKE) with auth, Cloud Trace, security unchanged
- **When to use a framework:** Complex multi-step processes needing hands-off execution, iterative model calls, context, tools, parallel jobs, failure recovery

## Technical Overview — https://adk.dev/get-started/about/

Core primitives: Agent (LlmAgent, workflow agents Sequential/Parallel/Loop), Tool, Callbacks, Session/State, Memory, Artifact, Code Execution, Planning, Models, Event, Runner.

Key capabilities:
1. Multi-agent system design (hierarchical, LLM transfer, AgentTool)
2. Rich tool ecosystem (FunctionTool, AgentTool, built-ins, external APIs, long-running tools)
3. Flexible orchestration (workflow agents + LLM dynamic routing)
4. Integrated dev tooling (CLI, Developer UI, event inspection, debugging)
5. Native streaming (Gemini Live API Toolkit, bidirectional text/audio)
6. Built-in agent evaluation (multi-turn datasets, local eval via CLI/dev UI)
7. Broad LLM support (BaseLlm interface)
8. Artifact management (ArtifactService, versioned files)
9. Extensibility / interoperability (third-party tools, MCP, connectors)
10. State and memory management (SessionService, Memory services)

## ADK 2.0 — https://adk.dev/2.0/

GA May 19, 2026. Features: graph-based workflows, dynamic workflows (code logic, loops, branching), collaborative workflows (coordinator + subagents).

Breaking changes from 1.x:
- Event schema: new `node_info` and `output` fields
- BaseAgent → BaseNode (agents are graph nodes; legacy `_run_async_impl` overrides ignored)
- No direct `session.events.append()` — must yield events
- Broad `except Exception` in tools disables automatic retries; never catch BaseException (breaks HITL)

Install 1.x: `pip install "google-adk~=1.0"`

## Graph routes — https://adk.dev/graphs/routes/

Workflow defined via `edges` array. Nodes: Agents, Tools, human input, Python functions. START keyword begins execution. Conditional routing via FunctionNode returning `Event(route=...)`. Parallel fan-out/fan-in with JoinNode. Nested Workflow objects as reusable nodes.

## Workflows overview — https://adk.dev/workflows/

Workflow types: Graph-based (2.0+), Dynamic (2.0+), Collaborative (2.0+, coordinator + subagents), Template (Sequential/Parallel/Loop agents). Benefits: predictability, reliability, structure. Experimental: Agent Routing (fallback, A/B, auto-routing).

## A2A Protocol — https://adk.dev/a2a/intro/

Agent2Agent standard for cross-service agent communication. Local sub-agents (in-process, fast) vs Remote A2A agents (separate services, cross-language). Use A2A for: third-party services, microservices, cross-language, formal API contracts. ADK: expose via A2AServer, consume via RemoteA2aAgent.

## Deployment — https://adk.dev/deploy/

Options: Agent Runtime (Agent Platform, managed auto-scaling), Cloud Run (container), GKE (Kubernetes, open models), other container infra (Docker/Podman, offline). agents-cli integration for Agent Runtime deploy.

## Evaluation — https://adk.dev/evaluate/

LLM agents need qualitative eval of trajectory + final output, not just pass/fail. Two components: (1) trajectory/tool-use vs expected steps, (2) final response quality. Test files (`.test.json`) for unit-style dev eval; Eval Set/Eval Case Pydantic schemas. Metrics: groundtruth-based and rubric-based tool use evaluation. Also: user simulation, environment simulation, custom metrics, optimization.
