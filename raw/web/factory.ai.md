## Factory Missions — https://docs.factory.ai/cli/features/missions

### What Missions do

Factory Missions are structured workflows for taking on large, multi-feature work with Droid. Instead of tackling everything in a single session, you collaborate with Droid upfront to build a plan — features, milestones, and skills needed — then hand off execution to an orchestration layer that manages the work. Access with `/missions`.

### How it works

1. Define your goal
2. Collaborate on the plan (features, milestones, ordering, skills)
3. Approve the plan
4. Droid enters Mission Control — orchestration view managing execution
5. Track, intervene, and redirect as needed

### The planning phase matters most

The biggest value in Missions is the planning phase. Getting the upfront plan right — features, ordering, milestones, skills — determines whether execution succeeds. Droid pushes back, asks questions, and iterates until the plan is solid.

**Validation:** Milestones define validation frequency. Validation workers run at the end of each milestone, verifying work.

**Estimating cost:** `total runs ≈ #features + 2 * #milestones`. This is a floor; validation may surface issues requiring follow-up.

### What Missions are good for

- Full-stack development — Complete applications with frontend, backend, database, and deployment
- Research — Deep investigation tasks requiring multiple approaches and structured output
- Brownfield migrations — Modernizing existing codebases, swapping frameworks, restructuring
- Ambitious prototypes — Product experiments that need to be functional, not just sketched out

### Working with Mission Control

Once a plan is approved, Droid enters Mission Control. Track progress, see which agents are working on what, and intervene. Missions are not fire-and-forget — treat yourself as project manager.

### Headless mission execution

```
droid exec --mission -f mission.md
droid exec --mission \
  --worker-model claude-sonnet-4-6 \
  --worker-reasoning-effort medium \
  --validator-model claude-opus-4-7 \
  --validator-reasoning-effort high \
  -f mission.md
```

### Configuration

- `missionModelSettings.workerModel` — Default model used by mission worker subagents
- `missionModelSettings.workerReasoningEffort` — Reasoning effort for workers
- `missionModelSettings.validationWorkerModel` — Model used by validation workers
- `missionModelSettings.validationWorkerReasoningEffort` — Reasoning effort for validators
- `missionModelSettings.skipScrutiny` — Skip scrutiny validation milestones
- `missionModelSettings.skipUserTesting` — Skip user-testing validation milestones
- `missionOrchestratorModel` — Model used by the mission orchestrator

## Skills — https://docs.factory.ai/cli/configuration/skills

Skills are **reusable capabilities** that extend what your Droid can do. Create a `SKILL.md` file with instructions, and the Droid adds it to its toolkit. The Droid uses skills when relevant, or you can invoke directly with `/skill-name`.

### Key properties

- **Flexible invocation** — Both you and the Droid can invoke skills
- **Composable** — Can be chained together as part of larger workflows
- **Token-efficient** — Lightweight and focused

### A skill can be

- A **workflow** — Step-by-step instructions (e.g., "navigate to URL, take screenshot, extract data")
- **Expertise** — Domain knowledge and conventions (e.g., "how we implement frontend features")
- **Both** — Instructions + tools + best practices bundled together

### Skill file format

```
---
name: summarize-diff
description: Summarize the staged git diff in 3–5 bullets. Use when the user asks for a summary of pending changes.
---

# Summarize Diff

## Instructions

1. Run `git diff --staged`.
2. Summarize the changes in 3–5 bullets, focusing on user-visible behavior.
3. Call out any migrations, risky areas, or tests that should be run.
```

### Where skills live

- **Workspace**: `<repo>/.factory/skills/` — Project skills shared with teammates; checked into git
- **Personal**: `~/.factory/skills/` — Private skills that follow you across projects
- **Compatibility**: `<repo>/.agent/skills/` — Discovered for compatibility

### Frontmatter reference

| Field | Required | Default | Description |
|---|---|---|---|
| `name` | No | Directory name | Display name for the skill |
| `description` | Recommended | — | What the skill does and when to use it |
| `user-invocable` | No | `true` | Set to `false` to hide from slash command menu |
| `disable-model-invocation` | No | `false` | Set to `true` to prevent Droid from auto-loading |

### Control who invokes a skill

| Frontmatter | User can /invoke | Droid can invoke |
|---|---|---|
| (default) | Yes | Yes |
| `disable-model-invocation: true` | Yes | No |
| `user-invocable: false` | No | Yes |

### Skills vs other configuration

- **Custom droids** — define which model and tools to use; full agent configurations
- **Legacy slash commands** (`.factory/commands/`) — superseded by skills
- **MCP servers** — connect external resources (APIs, databases, SaaS tools)
- **Skills** — package how work should be done; reusable, composable capabilities

### Skill cookbook categories

1. Frontend implementation skills
2. Service integration skills
3. Data querying skills
4. Internal tools skills
5. Browser automation skills
6. Automated QA skills
7. AI data analyst skills
8. Product management skills
9. Vibe coding skills

## Hooks — https://docs.factory.ai/cli/configuration/hooks-guide

Droid hooks are user-defined shell commands that execute at various points in Droid's lifecycle. They provide deterministic control over Droid's behavior.

### Example use cases

- **Notifications** — Customize how you get notified when Droid is awaiting input
- **Automatic formatting** — Run `prettier` on .ts files, `gofmt` on .go files after every edit
- **Logging** — Track and count all executed commands for compliance or debugging
- **Feedback** — Provide automated feedback when Droid produces code that doesn't follow conventions
- **Custom permissions** — Block modifications to production files or sensitive directories

### Hook Events

- **PreToolUse** — Runs before tool calls (can block them)
- **PostToolUse** — Runs after tool calls complete
- **UserPromptSubmit** — Runs when the user submits a prompt
- **Notification** — Runs when Droid sends notifications
- **Stop** — Runs when Droid finishes responding
- **SubagentStop** — Runs when sub-droid tasks complete
- **PreCompact** — Runs before Droid runs a compact operation
- **SessionStart** — Runs when Droid starts or resumes a session
- **SessionEnd** — Runs when Droid session ends

### Hook configuration example (logging)

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Execute",
        "hooks": [
          {
            "type": "command",
            "command": "jq -r '.tool_input.command' >> ~/.factory/bash-command-log.txt"
          }
        ]
      }
    ]
  }
}
```

### File Protection Hook example

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Create|Edit|ApplyPatch",
        "hooks": [
          {
            "type": "command",
            "command": "jq -r '.tool_input.file_path' | { read file_path; if echo \"$file_path\" | grep -q '\\.ts'; then npx prettier --write \"$file_path\"; fi; }"
          }
        ]
      }
    ]
  }
}
```
