## One-take Creation, Flexible Referencing: Introducing Seedance 2.5 — https://seed.bytedance.com/blog/one-take-creation-flexible-referencing-introducing-seedance-2-5

Date: 2026-07-31

Today, we are officially launching Seedance 2.5, the new-generation video creation model. Since the release of Seedance 2.0, we have noticed a shift in what users expect from video creation models: from merely generating a clip to completing a creative work. Building on the unified multimodal audio-video joint-generation architecture of Seedance 2.0, Seedance 2.5 centers on foundational generation and reference-based generation, delivering major breakthroughs in long-form storytelling, multimodal reference, and editing.

Key highlights:
1. Up to 30 seconds per generation, with multi-round extensions: high-quality 30-second audio-video clips in a single pass; supports multiple rounds of extension; improves shot transitions and scene changes; gains in image, audio, and motion quality. Users can produce high-quality multi-minute content with a consistent audiovisual language.
2. Fully upgraded multimodal referencing: up to 30 images, 10 video clips, and 10 audio clips as reference materials in a single pass. Strengthens clay render, motion, and creative references; multi-subject/scene/shot-change ideas.
3. More precise and stable editing: timestamp-level control for targeted editing of audio and video; green screen, camera perspective, and reference-based editing for film/advertising.

Availability (launch post): rolling out on Jimeng AI, Doubao Pro, and other platforms, with API access coming soon via BytePlus ModelArk.
Access paths cited:
- Project homepage: https://seed.bytedance.com/seedance2_5
- Jimeng Web -> Video Generation -> Select Seedance 2.5
- Doubao Pro -> Video Generation -> Select Seedance 2.5

### 30-second long-form storytelling with multi-round extensions
- Single-pass generation extended from 15 to 30 seconds.
- Within 30 seconds can organize multiple logically connected shots (setup, development, turning points, resolution).
- Multi-round extension maintains consistency of main characters, environments, and narrative pacing for multi-minute outputs.
- Optimizes textures, skin/eyes, lighting, color saturation; minimizes uncontrolled subtitles/BGM.

### Comprehensive upgrades to multimodal reference
- Up to 30 images + 10 videos + 10 audios per pass.
- Clay render referencing: textureless 3D models for spatial structure, poses, motion paths, camera angles; lighting follows physical laws from clay spatial info.
- Preserves appearances and voices of multiple characters in complex multi-character shots.

### More precise and reliable editing
- Timestamp-level prompt control during generation.
- Post-generation targeted modifications within clips while maintaining continuity.
- Green screen editing replaces backgrounds while keeping subject and physical responses (clothes, hair, gait, lighting).
- Camera perspective editing and reference-based editing.

### Industry scenarios
- Education: instructional videos, historical/scientific visualizations (e.g. Doubao Classroom).
- Industrial manufacturing / embodied intelligence / autonomous driving: synthetic video for robot training, industrial simulation, long-tail AV scenarios.

### Looking forward
- Room to improve: physical plausibility of complex motions; stability with multi-subject interactions.

Dreamina Seedance 2.5 tutorial
Dreamina Seedance 2.5 (hereinafter referred to as Seedance 2.5) is a next-generation video creation model with major improvements in long-form storytelling, omni reference support, and editing. It can generate up to 30 seconds of video in one request, extend videos over multiple rounds, accept up to 50 omni reference assets per request, and perform precise timestamp-based editing. Improved visual quality produces results with a more realistic, cinematic look.​
This tutorial introduces the key capabilities and usage of Seedance 2.5 to help you call the Create video generation task API.​

Read before use​
danger​
Seedance 2.5 has special constraints for video editing, first-frame/first-last-frame video generation, and video extension tasks. Violating these constraints triggers an error.​
Before calling the model, read the following carefully and make sure the task type, prompt intent, and parameter configuration are consistent.​
Task types and constraints​
Seedance 2.5 determines the task type based on the input assets and prompt intent. Task types include text-to-video, first-frame/first-last-frame video generation, and omni reference-to-video tasks. Omni reference-to-video tasks are further divided into three subtasks based on prompt intent: reference-to-video, video editing, and video extension.​
​
Task type​
	
Trigger condition​
	
Special constraints​


Text-to-video​
	
Only a text prompt is provided.​
	
No special constraints on ratio or duration.​


First-frame/first-last-frame video generation​
	
content.role is set to first_frame or last_frame.​
	
ratio must be adaptive.​
The model automatically keeps the output video aspect ratio consistent with the first-frame image specified by first_frame.​


Omni reference video generation​
	
Reference-to-video​
	
content contains at least one reference asset whose role is reference_image, reference_video, or reference_audio.​
	
No special constraints on ratio or duration.​


Video editing​
	
content contains at least one reference video whose role is reference_video, and the prompt expresses an editing intent.​
	
ratio must be adaptive, and duration must be -1.​
The model selects the video to edit based on the prompt intent and automatically keeps the output video aspect ratio and duration consistent with the selected video.​
The reference video must be 4–30 seconds long.​


Video extension​
	
content contains at least one reference video whose role is reference_video, and the prompt expresses an extension intent.​
	
ratio must be adaptive.​
The model selects the video to extend based on the prompt intent and automatically keeps the output video aspect ratio consistent with the selected video.​


​
Note​
To reduce asynchronous errors caused by special constraints, omni reference-to-video tasks can use omni_reference_task_type to explicitly guide the task type and move validation earlier. For details, see the configuration methods below.​
Configuration methods​
Omni reference-to-video without specifying a subtask​
For an omni reference-to-video task, if you do not explicitly distinguish the specific subtask type, use the following recommended parameter configuration:​
Set omni_reference_task_type to auto.​
Set content.role to reference_image, reference_video, or reference_audio.​
We recommend setting ratio to adaptive and duration to -1. If you provide reference videos, we recommend that each video be 4–30 seconds long.​
Note​
When omni_reference_task_type is set to auto, the model may classify the task as reference-to-video, video editing, or video extension based on the prompt intent. Video editing and video extension have special parameter constraints. Using the recommended configuration satisfies these constraints and reduces asynchronous errors after task creation.​
Video editing​
Edit the visuals or audio of an original video, such as replacing the video subject, adding or removing objects in the video, or redrawing or repairing part of the frame.​
For a clear video editing task, use the following configuration method:​
Set omni_reference_task_type to edit.​
Include at least one reference video whose role is reference_video in content.​
ratio must be adaptive; duration must be -1; the reference video must be 4–30 seconds long.​
The prompt must include at least one keyword or phrase such as edit the video, add, delete/remove, or modify/replace/change.​
Prompt examples: Add some little animals to @Video 1; replace the character in @Video 1 with the character in @Image 1; remove the background music from @Video 1.​
Video extension​
Extend an original video forward or backward.​
For a clear video extension task, use the following configuration method:​
Set omni_reference_task_type to extend.​
Include at least one reference video whose role is reference_video in content.​
ratio must be adaptive.​
The prompt must include at least one keyword or phrase such as extend forward/backward, continue, or continue the story.​
Prompt examples: Extend @Video 1 backward, and have the character in @Image 1 descend from the sky; continue the 5 seconds before @Video 1, with the woman in @Video 2 entering the frame and speaking.​
First-frame/first-last-frame video generation​
Input one image as the first frame, or two images as the first and last frames, to generate a video.​
content must contain an image whose role is first_frame. First-last-frame video generation must also contain an image whose role is last_frame.​
ratio must be adaptive.​
Error handling​
Seedance 2.5 validates parameters when a task is submitted and again after the task starts.​
Synchronous validation (when submitting a task)​
For omni reference-to-video tasks, when omni_reference_task_type is explicitly set to edit or extend, the API validates the special parameter constraints earlier. If the request does not meet the requirements, the API immediately returns an error.​
Note​
When actually processing the task, the model still further determines the task type based on the prompt. If the actual task type identified by the model does not match the specified value, the task still triggers an asynchronous error (error code: InvalidParameter.TaskTypeMismatch). Follow the prompting guidance for each task type to reduce the chance of errors.​
Asynchronous validation (after a task starts)​
For omni reference-to-video tasks, when omni_reference_task_type is omitted or set to auto, the model first determines the actual task type from the input assets and prompt, and then validates the special parameter constraints for that task type. If the request does not meet the requirements, the task returns an error asynchronously.​
For first-frame/first-last-frame video generation, if the parameter configuration does not meet the special constraints for the task, the task returns an error asynchronously.​
Note​
Asynchronous errors caused by incompatibility between parameter configuration and task type return the error code InvalidParameter.TaskTypeConstraint.​
