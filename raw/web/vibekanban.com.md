## Why we're building this

The new bottleneck is planning and review

In the old world you could expect software to get shipped at the speed at which a software engineer could work through each task sequentially. In the new world, the coding agents work on infinite tasks in parallel, but you still need to plan and review that work as a human. This means the speed of shipping is now limited by how quickly you can plan and review, making these crucial areas to optimise.

Run coding agents in parallel to eliminate idle time

As coding agents get more capable, they tend to work for longer before needing human review. If you work with a single agent at a time, that creates periods of time when you're blocked, waiting for that one agent to finish. You can remove that dead time by splitting work into multiple streams, run several agents in parallel, and switch your attention to whatever's ready to review.

The SOTA will change

Foundational model labs and application layer startups will continuously leap-frog each other to build state-of-the-art coding agents over the next 12m+. You shouldn't have to change your workflow or behaviour to be able to try out different coding agents.

## Get Started — https://vibekanban.com/docs/getting-started.md

Launch Vibe Kanban, connect a coding agent, and go from zero to pull request.

Vibe Kanban keeps you organised while running multiple coding agents in parallel by streamlining how you plan and review their work.

1. Launch Vibe Kanban: `npx vibe-kanban`
2. Confirm preferences (coding agent, IDE, notification preferences)
3. Sign in with GitHub or Google (optional — skip for local-only use)
4. Navigate the kanban board — auto-created personal org and initial project
5. Create an issue — title + description become the agent's prompt; supports priorities, tags, parent/child relationships
6. Create a workspace — automatically creates git worktrees for selected repositories and launches the coding agent
7. Review in workspaces view — full diff review, browser testing

## Issue Management — https://vibekanban.com/docs/issue-management.md

Create, organise, and track issues from first draft to done on the kanban board.

Issues are the fundamental unit of work in Vibe Kanban — they represent a bug, feature, or piece of work. The issue description becomes the prompt the coding agent receives.

Key concepts:
- Create issues from the + button on column headers or the New Issue button
- Title + description → agent prompt; use clear, specific titles
- Priority levels: Urgent / High / Medium / Low
- Tags for categorisation (project-specific)
- Parent/child relationships for linked issues
- Kanban columns: drag-and-drop to change status
- Filter by Team (all issues) or Personal (assigned to you)
- List view for tabular browsing

## Workspaces Overview — https://vibekanban.com/docs/workspaces/index.md

A redesigned task execution experience with multi-repo support, multiple agent sessions, and an integrated preview browser.

A workspace is an isolated environment for completing a coding task. It is a "project room" where you:
1. Work on a specific task
2. Chat with coding agents
3. Review changes
4. Test your application
5. Create pull requests

Key concepts:
- **Workspace**: task execution environment for one goal
- **Repository**: a git repo included in the workspace (each has independent git state)
- **Session**: a conversation thread with a coding agent

How they relate: A workspace can contain one or more repositories; within a workspace, you can have multiple sessions.

Key features:
- Multi-Repository Support — work across multiple repos in one workspace
- Multiple Sessions — run parallel agent conversations; work around token limits
- Browser Testing — built-in browser preview with devtools and device emulation
- Changes Panel — syntax-highlighted diffs with inline commenting
- Integrated Terminal — run commands directly
- Workspace Notes — documentation per workspace
- Command Bar — Cmd/Ctrl+K for all actions

On workspace creation: Vibe Kanban creates a git worktree (a separate working directory linked to a new branch). Main branch is safe; all changes are isolated.

## Reviewing Code — https://vibekanban.com/docs/reviewing-code.md

Review diffs, add inline comments, and send feedback to your coding agent.

After a coding agent finishes work, you review its changes, leave inline comments, and send the agent back to address them. The review-feedback-fix loop repeats until satisfied.

Steps:
1. Open the changes panel (Toggle Changes Panel button, app bar changes icon, or Cmd/Ctrl+K)
2. Navigate the file tree — click any file to see its diff; search box to filter
3. Read diffs — green for additions, red for deletions, grey for context. Toggle Unified / Side-by-Side view modes
4. Add inline comments — hover a diff line, click the comment icon; write specific, actionable feedback
5. Send feedback to the agent — submit comments from the changes panel; agent receives them in the chat

## Shutdown announcement — https://vibekanban.com/blog/shutdown

Today we're shutting down bloop, the company behind Vibe Kanban. The Vibe Kanban project will live on, open source and community maintained.

Thousands of software engineers use Vibe Kanban every day to ship more with coding agents, but the vast majority are free users and we couldn't find a business model that we could get excited about.

We launched in June 2025 and were the first to ship multi-agent support, diff commenting, live preview, click-to-edit, remote access and many other features that are now taken for granted.

We're not out of ideas and believe there is a non-commercial future for the project. We'll release a roadmap for the community maintained edition over the next few weeks.

The latest version includes a data export feature. Remote services will remain available for 30 days, after which Vibe Kanban will transition to a fully local architecture. Remote services that will be removed: kanban issues, comments, projects and organisations. Local workspaces will continue to function.
