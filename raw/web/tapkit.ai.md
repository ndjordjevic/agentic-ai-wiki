## Landing page — https://www.tapkit.ai/
How does TapKit work?

TapKit gives you programmatic control of real, physical iPhones through Apple's accessibility features. You send actions (tap, swipe, type) via our API, and they execute on your iPhone. For framework differences, [compare TapKit with Appium](/compare/tapkit-vs-appium).

Is this the same as an iOS simulator?

No. Simulators run virtual iOS environments that can't install or use apps. TapKit runs on real iPhones. See the full [TapKit vs iOS simulator comparison](/compare/tapkit-vs-ios-simulator).

What apps can TapKit use?

Anything on the App Store you can use.

Why use TapKit instead of a social posting API?

Use a posting API when an endpoint covers the whole job. Use TapKit when an authorized agent needs the actual mobile app, including drafts, notifications, account switching, verification, or cross-app steps. Read the full [TapKit vs posting APIs comparison](/compare/tapkit-vs-posting-apis).

How do I connect my AI agent?

Use our MCP server to connect directly to Claude Code or Cursor, our REST API with a Python SDK for custom integrations, or our Mac and Web apps for no-code control. The typical agent loop is: screenshot → send to your vision model → get action → execute on device. See how TapKit compares with [iPhone Mirroring MCP](/compare/tapkit-vs-iphone-mirroring-mcp).

Do I need my own iPhone?

Yes, TapKit is bring-your-own-device. You connect your own iPhone to your Mac and TapKit turns it into an API. We're exploring hosted phone options for teams that don't want to manage their own hardware. If you're evaluating hosted hardware, compare TapKit with [device farms](/compare/tapkit-vs-device-farms).

What does it cost?

Tapkit costs $49 per month per phone. One phone is $49/month and five phones are $245/month. Contact us for fleet setup and onboarding.

What is an iPhone agent?

An iPhone agent is an AI that can see the phone's screen, decide what to do next, and act with taps, swipes, and typing. It checks the screen again after each step to work toward your request. Tapkit gives the agent access to a real iPhone and the controls to use it.

Why use a real iPhone?

A real iPhone has the App Store apps, signed-in accounts, notifications, and permissions you use every day. That lets an agent work through mobile workflows even when an API is missing. See how Tapkit compares with the [iOS Simulator](/compare/tapkit-vs-ios-simulator) and [Appium](/compare/tapkit-vs-appium).

Do I need to build a new agent?

Bring the agent you already use. Tapkit connects your iPhone as a tool, so your agent doesn't have to run inside an iOS app. Follow the [MCP setup](/integrations/mcp) to connect an existing agent, or use the [REST API and Python SDK](/api) in your own workflows.

# Introduction

> Give your agent an iPhone

TapKit lets AI agents use real iPhones. Plug an iPhone into a Mac running the TapKit app, and an agent can take screenshots of it, tap, and type. The agent can be TapKit's built-in agent, Claude, Codex, or your own code.

Nothing is installed on the iPhone. You don't need to jailbreak it, turn on developer mode, or use a simulator.

# MCP

> Connect any MCP client to TapKit

TapKit runs a hosted MCP server. Any client that supports remote MCP servers with OAuth can connect to it. The only thing you run locally is the [Mac app](/setup).

```
https://mcp.tapkit.ai/mcp
```

The server uses the Streamable HTTP transport.

## Connect

Most clients accept a config like this:

```json theme={null}
{
  "mcpServers": {
    "tapkit": {
      "type": "http",
      "url": "https://mcp.tapkit.ai/mcp"
    }
  }
}
```

Point your MCP client at the URL. The client must support OAuth 2.1 with PKCE and dynamic client registration. The server publishes its OAuth metadata at `/.well-known/oauth-protected-resource/mcp`.

## Sign in

The first time your client connects, it opens TapKit in your browser. Sign in with Google, then click **Allow access** to let the client view and interact with your connected iPhones.

The MCP server only accepts OAuth. [API keys](/web-app#api-keys) are for the [REST API](/api-reference/introduction).

## Tools

Start with `list_phones`. Every other tool takes the `phone_id` it returns.

| Tool | Parameters | Description |
| - | - | - |
| `list_phones` | None | List phones with their IDs, status, and screen size |
| `get_phone_status` | `phone_id` | Connection status and screen size of one phone |
| `screenshot` | `phone_id` | Capture the screen as an image |
| `tap` | `phone_id`, `x`, `y` | Tap a point |
| `double_tap` | `phone_id`, `x`, `y` | Double tap, for zooming or selecting a word |
| `triple_tap` | `phone_id`, `x`, `y` | Triple tap, for selecting a line or paragraph |
| `long_press` | `phone_id`, `x`, `y`, `duration`? | Press and hold, for context menus. `duration` is in ms, default 1000 |
| `flick` | `phone_id`, `x`, `y`, `direction` | Quick swipe `up`, `down`, `left`, or `right` from a point |
| `drag` | `phone_id`, `from_x`, `from_y`, `to_x`, `to_y`, `speed`? | Press, move, and release. `speed` is `slow`, `medium`, or `fast`, default `medium` |
| `hold_and_drag` | `phone_id`, `from_x`, `from_y`, `to_x`, `to_y`, `hold_duration_ms`?, `speed`? | Long press, then drag, for moving items. Hold defaults to 500 ms |
| `type_text` | `phone_id`, `text` | Type into the focused field. US-ASCII only, up to 100 characters |
| `press_key` | `phone_id`, `key`, `modifiers`?, `repeat`? | Press `enter`, `escape`, `backspace`, or an arrow key, optionally holding `control`, `shift`, `alternate`, or `command` |
| `press_home` | `phone_id` | Go to the Home Screen |

## Coordinates

Screenshots are JPEGs scaled so the long edge is at most 1344 pixels. Tool coordinates are pixels in that image, measured from the top-left corner. The server converts them to the phone's native resolution.

Action tools don't return a screenshot. Call `screenshot` after an action to see the result.

## Limits

Each connection can make 300 requests per minute. Agents can only control phones that are online and active on your subscription.

# API overview

> Control connected iPhones over HTTP

The REST API sends touch and keyboard input to your iPhones and takes screenshots. It has the same actions that agents get through [MCP](/integrations/mcp), for code that doesn't use an agent framework.

## Base URL

```
https://api.tapkit.ai/v1
```

## Authentication

Send an API key in the `X-API-Key` header. Create keys in the [web app](/web-app#api-keys). Keys start with `tk_`.

```bash theme={null}
curl https://api.tapkit.ai/v1/phones \
  -H "X-API-Key: $TAPKIT_API_KEY"
```

A key has access to every phone in your organization. Keep it out of source control and client-side code.

## Before you call an action

A phone accepts actions when its Mac app is open and signed in, the phone is connected, unlocked, and set up in the Mac app, and the phone is active on your subscription.

[List phones](/api-reference/list-phones) returns each phone's ID and `connection_status`.

## Coordinates

Coordinates are integer pixels on the phone's screen, measured from the top-left corner. They match the pixels of a [screenshot](/api-reference/screenshot). [List phones](/api-reference/list-phones) reports each screen's `width` and `height`.

## Jobs

Every action runs as a job on the phone's Mac. By default, a request waits up to 60 seconds for the job to finish and then returns it:

```json theme={null}
{
  "id": "5d2c9a0e-7f7b-4c1e-9d1a-2f4b8e0c3a61",
  "status": "completed",
  "result": {},
  "created_at": "2026-09-23T18:30:00Z",
  "completed_at": "2026-09-23T18:30:01Z"
}
```

`status` is `pending`, `running`, `completed`, or `failed`. A failed action still returns HTTP 200, with the reason in `result.error`. If an action doesn't finish in 60 seconds, its job fails with `"error": "TIMEOUT"`.

Add `?async=true` to get the job ID back immediately, then poll [Get job](/api-reference/get-job):

```json theme={null}
{ "job_id": "5d2c9a0e-7f7b-4c1e-9d1a-2f4b8e0c3a61" }
```

## Errors

Other errors return an HTTP error status, with details under `detail`:

```json theme={null}
{
  "detail": {
    "error": "PHONE_NOT_FOUND",
    "message": "Phone not found",
    "context": { "phone_id": "..." }
  }
}
```

| Status | `error` | Meaning |
| - | - | - |
| 401 | `AUTH_REQUIRED` | No `X-API-Key` header |
| 401 | `INVALID_API_KEY` | The key is wrong or revoked |
| 402 | `SUBSCRIPTION_REQUIRED` | Your organization has no active subscription |
| 404 | `PHONE_NOT_FOUND` | No phone with that ID in your organization |
| 409 | `PHONE_INACTIVE` | The phone isn't active on your subscription. Activate it in the [web app](/web-app#phones). |
| 400 | `MAC_APP_NOT_RUNNING` | The phone's Mac app isn't connected |
| 408 | `TIMEOUT` | A screenshot didn't arrive in time |
