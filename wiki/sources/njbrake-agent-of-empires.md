Agent of Empires (AoE) is an open-source terminal session manager for AI coding agents, written in Rust and available under the MIT license. With 1,868 stars and 153 forks, it sits at the intersection of multi-agent tooling and developer workflow — it lets you run Claude Code, OpenCode, Mistral Vibe, Codex CLI, Gemini CLI, Cursor CLI, Copilot CLI, Pi.dev, Factory Droid, and Hermes in parallel, each in its own isolated tmux session, managed from a single TUI, web dashboard, or CLI. It matters for this wiki as a concrete example of an agent orchestration layer that is not an LLM framework: it handles session persistence, parallel branch isolation via git worktrees, Docker sandboxing, status detection, and remote mobile access without touching model APIs directly.

_All claims below are sourced from ../../raw/github/njbrake-agent-of-empires.md unless otherwise noted._

## What it does

AoE wraps tmux to give each AI coding agent its own persistent session so that agents keep running when the user closes the terminal, disconnects SSH, or switches devices. Its TUI surfaces all running sessions in one status column with agent-aware state detection — running, waiting for input, idle, or error — and lets the operator attach, detach, delete, or create sessions without touching tmux directly. The web dashboard (React + xterm.js, installable as a PWA) renders the real agent terminal in the browser, enabling control from a phone or tablet. Remote access is handled automatically by pressing `R` in the TUI: it exposes the dashboard over HTTPS using Tailscale Funnel when available, falling back to a Cloudflare Tunnel, with QR code + passphrase auth.

## Installation

Prerequisites: tmux (required), Docker (optional for sandboxing).

```bash
# Quick install (Linux & macOS)
curl -fsSL \
  https://raw.githubusercontent.com/njbrake/agent-of-empires/main/scripts/install.sh \
  | bash

# Homebrew
brew install aoe

# Nix
nix run github:njbrake/agent-of-empires

# Build from source
git clone https://github.com/njbrake/agent-of-empires
cd agent-of-empires && cargo build --release
```

The TUI-only build (`cargo build --release`) requires no JavaScript tooling. The web dashboard build (`cargo build --features serve`) requires Node.js + npm; `build.rs` runs `npm install && npm run build` in `web/` when inputs change.

## Key features

- **Multi-agent support** — auto-detects Claude Code, OpenCode, Mistral Vibe, Codex CLI, Gemini CLI, Cursor CLI, Copilot CLI, Pi.dev, Factory Droid, and Hermes; each runs in its own named tmux session.
- **TUI** — built with ratatui; session list with status column, diff viewer, settings panels, and an inline help overlay. Keybinding `?` shows all context-sensitive shortcuts.
- **Web dashboard (Beta)** — React 19 + xterm.js v6 + Tailwind v4; renders the live agent terminal; installable as a PWA; token-based auth; launched via `aoe serve`.
- **Remote phone access** — `R` in TUI starts HTTPS tunnel (Tailscale Funnel preferred, Cloudflare fallback) with QR code and passphrase; stable URL across restarts when using Tailscale.
- **Git worktrees** — creates isolated worktrees so multiple agents can work on different branches of the same repo simultaneously without conflicts.
- **Docker sandboxing** — runs agents inside containers with shared auth volumes; Docker is optional and detected at runtime.
- **Diff view** — review and stage git changes without leaving the TUI.
- **Profiles** — separate named workspaces for different projects or clients, each with independent session lists and settings.
- **Sound effects** — audible status notifications (bundled audio files) when agents change state.
- **CLI** — `aoe add --cmd <tool>`, `aoe serve`, `aoe session`, and more; integrates with tools like OpenClaw.

## Architecture

AoE is a Rust workspace (`Cargo.toml` v1.5.0, edition 2021, MSRV 1.85) with a modular `src/` layout:

- `src/cli/` — clap 4.6 command handlers; CLI reference auto-generated by `cargo xtask gen-docs`.
- `src/tui/` — ratatui 0.30 + crossterm 0.29 UI and input handling; all panels, dialogs, and settings live here.
- `src/session/` — session storage, configuration, and profile/group management.
- `src/tmux/` — tmux integration; the core abstraction that starts, stops, attaches, detects status, and lists sessions.
- `src/process/` — OS-specific process handling (`macos.rs`, `linux.rs`) to keep platform `cfg` checks centralized.
- `src/docker/` — Docker container management and sandboxing configuration.
- `src/git/` — git worktree operations and template resolution.
- `src/server/` — axum HTTP server + REST API + WebSocket PTY relay + token auth; the backend for the web dashboard.
- `src/migrations/` — versioned data migrations; `.schema_version` tracks state; `migrations::run_migrations()` runs on every startup.
- `web/` — React + TypeScript frontend; Vite + Tailwind v4 + xterm.js v6; built at compile time via `build.rs` when `--features serve` is set.
- `website/` — Astro static site for the public marketing site at agent-of-empires.com.
- `contrib/` — community-maintained integrations (currently an OpenClaw skill).

Runtime data on Linux lives under `$XDG_CONFIG_HOME/agent-of-empires/`; on macOS under `~/.agent-of-empires/`. The `aoe serve` daemon writes `serve.pid`, `serve.url`, `serve.mode`, and `serve.passphrase` to the app dir for reattach and TUI display.

## Example usage

```bash
# Launch the TUI
aoe

# Add a session running Claude Code
aoe add --cmd claude

# Add a session on a new git worktree branch
aoe add --cmd "claude" --worktree feature/new-thing

# Start the web dashboard (then visit the printed URL)
aoe serve

# Expose dashboard remotely with HTTPS (Tailscale / Cloudflare auto-selected)
# Press R inside the TUI

# Run inside a Docker sandbox
aoe add --cmd claude --sandbox
```

Inside the TUI, `Ctrl+b d` detaches from an agent session and returns to the dashboard. `?` shows all keybindings. For SSH mobile clients (Termius, Blink), wrap in a tmux session first: `tmux new-session -s main && aoe`.

## When to use

- You run multiple AI coding agents (Claude Code, Codex, Gemini CLI, etc.) in parallel across different branches and need one place to see which are running, waiting, or idle.
- You want session persistence so agents survive terminal crashes, SSH disconnects, or machine sleeps.
- You need to review an agent's output or intervene from your phone without setting up a separate remote desktop.
- You want git worktree isolation so parallel agents don't step on each other's working trees.
- You want Docker-sandboxed agent execution without scripting the container lifecycle yourself.

AoE is a session manager, not an agent framework — it does not route messages between agents, enforce budgets, or provide governance. For control-plane concerns (approval gates, cost limits, org charts), pair it with a platform like [[paperclip.ing]].
