## API Reference — https://resend.com/docs/api-reference/introduction

The Resend API is a REST service using HTTPS connections to `https://api.resend.com`.

**Authentication:** Authorization header formatted as `"Bearer re_xxxxxxxxx"` using an API Key, plus a mandatory User-Agent header to avoid 403 errors.

**Response codes:** Standard HTTP conventions: 2xx success, 4xx user errors, 5xx server errors. Key codes: 200 (success), 400 (parameter issues), 401 (missing key), 403 (invalid key), 404 (not found), 429 (rate limit exceeded).

**Rate limits:** Default `5 requests per second per team` across all associated API keys. Can be increased for qualified senders.

**Pagination:** Cursor-based. **API versioning:** Not yet implemented, planned using calendar-based headers.

## Broadcasts — https://resend.com/docs/dashboard/broadcasts/introduction

Resend Broadcasts is a no-code feature for sending marketing emails (newsletters, product launches, investor updates, promotions, changelogs) without writing code.

**Features:**
- Built-in editor with markdown support, custom styling (colors and typography), dynamic placeholders (contact names, unsubscribe URLs)
- Test Email function to preview in personal inboxes before sending
- Bulk operations: delete drafts or cancel scheduled sends; keyboard shortcuts (Cmd+A)
- Status tracking: draft, scheduled, sent, queued — only drafts can be deleted
- CSV export for emails, broadcasts, contacts, segments, domains, logs, API keys (≤1,000 items immediate; larger via email link valid 7 days)
- Template reuse: sent broadcasts can be cloned as reusable templates for transactional emails

## Domains — https://resend.com/docs/dashboard/domains/introduction

Resend requires verified domain ownership for sending and receiving emails. Domain management available via dashboard, API, CLI, and MCP server.

**Domain status types:** `not_started`, `pending`, `verified`, `partially_verified`, `partially_failed`, `failed` (no DNS records within 72 hours), `temporary_failure` (previously verified, rechecked for 72 hours).

**Subdomain strategy:** Recommended to use subdomains like `updates.example.com` rather than root domains. Each subdomain requires independent verification.

**Configuration:** Open and click tracking, Enforced TLS (prevents sending if receiving server lacks TLS), custom return path (must be ≤63 chars, start with letter, contain only letters/numbers/hyphens).

**DNS authentication:**
- **SPF (Sender Policy Framework):** Authorises IP addresses permitted to send email on behalf of a domain.
- **DKIM (DomainKeys Identified Mail):** Verifies email was authorised by the domain owner.
