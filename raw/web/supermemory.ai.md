## Docs — https://supermemory.ai/docs/

Supermemory is described as "the long-term and short-term memory and context infrastructure for AI agents." The platform achieves state-of-the-art performance on benchmarks including LongMemEval and LoCoMo.

### Core Components

The system integrates four primary elements:
- Agent memory via graph-based structures
- Content extraction across multiple formats
- Data connectors and synchronization capabilities
- A managed RAG platform

### How It Functions

The workflow involves three steps: users submit text, files, and conversations to Supermemory; the system "intelligently indexes them and builds a semantic understanding graph" on an entity (user, document, project, or organization); and at query time, relevant context is retrieved for language models.

### Three Context Approaches

**Memory API** extracts and maintains evolving user facts in real time, handling knowledge updates and temporal changes to create dynamic user profiles.

**User Profiles** combine static information the agent should always know with dynamic, episodic data from recent interactions.

**RAG** provides advanced semantic search with metadata filtering and contextual chunking.

All three approaches "share the same context pool when using the same user ID (`containerTag`)" allowing flexible implementation strategies.

### Getting Started

Documentation offers a quickstart guide for initial API calls, conceptual material on knowledge graph architecture, and self-hosting instructions for offline deployment.

## Quickstart — https://supermemory.ai/docs/quickstart

Supermemory enables developers to integrate persistent memory into LLM applications. The platform automatically extracts memories from conversations and maintains user profiles.

### Getting Started

Users begin by obtaining an API key through the Developer Platform (console.supermemory.ai), then installing the appropriate SDK for their language (Python or TypeScript).

### Core Functionality

The API provides two main operations:

1. **Profile retrieval**: "Get user profile + relevant memories for context" by querying with a container tag and search term
2. **Memory storage**: Add conversation content for future retrieval using the `add()` method

### Key Features

Supermemory automatically: Extracts memories from conversations, Builds and maintains user profiles (static facts + dynamic context), Returns relevant context for personalized LLM responses.

Developers can refine search results using a `threshold` parameter to filter by relevance score (e.g. `threshold=0.7`).

The platform also offers self-hosting as a single binary and integration with the Vercel AI SDK.

## SDK — https://supermemory.ai/docs/integrations/supermemory-sdk

### Available SDKs

Python and JavaScript implementations:
- Python: `pip install supermemory`
- JavaScript: `npm install supermemory`

### Key Operations

1. **Adding memories** with optional metadata and container tags for organization
2. **Searching** through stored memories with filtering capabilities
3. **Profile retrieval** to access both static and dynamic user information

### Configuration

Both SDKs support custom deployment. Users can specify alternative endpoints via `baseURL` (TypeScript) or `base_url` (Python) for self-hosted instances.

Additional operations include document listing, deletion, and advanced search filtering using AND logic conditions based on metadata attributes.

## MCP — https://supermemory.ai/mcp

Supermemory offers a Model Context Protocol (MCP) server enabling AI tools to access shared memory. Addresses "context amnesia" across multiple AI applications.

### Key Features

- Universal compatibility: Claude, Cursor, VS Code, Windsurf, ChatGPT, Cline, and other MCP-compatible clients
- Instant search across conversations
- Automatic knowledge preservation
- Style and preference retention
- Seamless context sharing without manual synchronization

### Setup

Installation: `npx -y mcp-remote@latest https://mcp.supermemory.ai/mcp`

Authentication uses OAuth (no API key management required). Once configured, all connected tools gain access to the user's complete memory.

### Use Cases

- Individual developers: personal context layer across all AI tools
- Teams: shared memory tagged to specific conversations, faster onboarding
