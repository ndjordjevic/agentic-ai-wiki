## Specs — https://kiro.dev/docs/specs/

Specs are structured artifacts that transform high-level ideas into detailed implementation plans.

Every spec generates three files:
- **requirements.md** (or **bugfix.md**) — user stories with acceptance criteria, or bug analysis
- **design.md** — technical architecture, sequence diagrams, implementation considerations
- **tasks.md** — discrete trackable tasks with real-time status updates

**Three-phase workflow:** Requirements/Bug Analysis → Design → Tasks

**Two spec types:**
- **Feature Specs** — requirements-first or design-first workflow; Quick Plan auto-generates all three artifacts
- **Bugfix Specs** — systematic root cause analysis, fix design, regression validation

**Parallel task execution:** Kiro builds a dependency graph of tasks.md, groups independent tasks into waves, and runs each wave concurrently — significantly reducing execution time for most feature specs.

**When to use Specs vs Vibe:**
- Specs: complex features, costly regressions, team collaboration, iterative requirements
- Vibe: quick exploratory coding, prototyping without clear goals

## Hooks — https://kiro.dev/docs/hooks/

Agent hooks are automated triggers that execute agent prompts or shell commands when specific events occur in the IDE.

**Storage:** `.kiro/hooks/` (workspace-level) or `~/.kiro/hooks/` (user-level). JSON files.

**Example hook:**
```json
{"version":"v1","hooks":[{"name":"lint-on-save","trigger":"PostFileSave","matcher":"\\.ts$","action":{"type":"command","command":"npm run lint"},"timeout":30,"enabled":true}]}
```

**Trigger types:**

| Trigger | Fires when | Can block? |
|---|---|---|
| SessionStart | Session begins | No |
| Stop | Agent completes its turn | No |
| PreToolUse | Before tool executes | Yes |
| PostToolUse | After tool executes | No |
| PreTaskExec | Before a spec task starts | Yes |
| PostTaskExec | After a spec task finishes | No |
| UserPromptSubmit | User submits a prompt | Yes |
| PostFileCreate | After a file is created by the agent | No |
| PostFileSave | After a file is saved by the agent | No |
| PostFileDelete | After a file is deleted by the agent | No |

Actions can be `{ type: "command", command: "..." }` or `{ type: "agent", prompt: "..." }`. Blocking hooks (exit code 2) can prevent tool use or prompt execution.

## Steering — https://kiro.dev/docs/steering/

Steering gives Kiro persistent knowledge about your workspace through markdown files.

**Scopes:**
- **Workspace:** `.kiro/steering/` — project-specific patterns, libraries, standards
- **Global:** `~/.kiro/steering/` — conventions for all workspaces; overridden by workspace steering

**Foundational steering files (auto-generated):**
- `product.md` — product purpose, target users, key features, business objectives
- `tech.md` — frameworks, libraries, tools, technical constraints
- `structure.md` — file organization, naming conventions, import patterns, architectural decisions

**Inclusion modes** (YAML front matter):
- Always included (default) — loaded into every interaction
- `fileMatch` — loaded only when working with matching files (`fileMatchPattern: "components/**/*.tsx"`)

Supports the AGENTS.md standard — AGENTS.md files in `~/.kiro/steering/` or workspace root are picked up automatically (always-included, no front-matter modes).
