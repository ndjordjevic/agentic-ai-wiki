[[paperclip.ing]] introduces Paperclip, an open-source control plane for running autonomous AI-agent companies. It sits above agent runtimes like Claude Code, Codex, Cursor, OpenClaw, bash agents, and HTTP bots and provides the organizational layer those runtimes lack: an org chart with hierarchical reporting, a heartbeat execution loop that wakes agents on schedule, an atomic ticket system with checkout locks, per-agent budget enforcement with hard stops, board-level governance and approval gates, and complete multi-company data isolation in a single Node.js + React deployment. The source also shows how Paperclip packages this operating model into both a public product site and a companion GitHub repo with a built-in heartbeat skill, plugin system, portability features, and an actively maintained roadmap.

[[sequentialthinking-mcp]] documents the Sequential Thinking MCP Server, a focused MCP server that exposes a single `sequential_thinking` tool for structured, revisable, branching reasoning inside an MCP-aware host. The source captures the tool's input schema, the intended problem-solving workflow, practical verification steps, and concrete installation patterns for Claude Desktop, VS Code, Codex CLI, NPX, and Docker.

[[langchain.com]] reframes LangChain as a multi-product agent-engineering platform rather than just a library. The umbrella source ties together [[langchain.com-langsmith]], [[langchain.com-fleet]], [[langchain.com-langchain]], [[langchain.com-langgraph]], and [[langchain.com-deepagents]] and shows how observability, no-code business agents, higher-level framework primitives, lower-level orchestration, and an autonomous agent harness are positioned as one integrated stack.

[[langchain.com-langsmith]] adds the operational layer to the wiki's agentic AI coverage: framework-agnostic tracing, offline and online evaluation loops, deployment options, Agent Server runtime architecture, and the production feedback cycle that turns traces into datasets and redeployable improvements. It is especially useful for understanding how agent teams move from experimentation to monitored production systems.

[[langchain.com-fleet]] contributes the no-code side of the LangChain ecosystem. It covers business-facing agents built from templates, integrations, channels, approvals, long-term memory files, and sub-agents, showing how LangChain's platform story extends beyond developer libraries into managed agent operations for non-engineering teams.

[[langchain.com-langchain]] documents the high-level open-source framework path: `create_agent`, model and tool abstractions, middleware-based dynamic routing, and the batteries-included approach to getting useful agents running quickly. It complements the lower-level orchestration material elsewhere in the wiki by covering the higher-abstraction starting point for code-first agent development.

[[langchain.com-langgraph]] captures the runtime-oriented end of the stack: explicit state graphs, durable execution, interrupt-driven human-in-the-loop patterns, workflow topologies like routing and orchestrator-worker, and thread-based resumption semantics. It adds a strong reference point for stateful, long-running agent systems that need more control than a single high-level agent loop.

[[langchain.com-deepagents]] adds the agent-harness layer to the wiki, completing the three-tier open-source stack under LangChain. It covers the Deep Agents SDK — a batteries-included framework built on LangGraph that adds planning with `write_todos`, file-system context management, subagent spawning, and long-term memory — together with the Deep Agents CLI, a terminal coding agent built on the same SDK. This is a new product added to the platform since the initial ingest.

[[runcabinet.com]] introduces Cabinet, a free and open-source self-hosted AI-first startup OS where all knowledge lives as markdown files on disk. It bridges the gap between note-taking tools (Obsidian, Notion) and agent orchestration platforms (Paperclip) by combining a WYSIWYG knowledge base, 20 pre-built AI agent templates with cron-based scheduling, embedded live HTML apps, a browser-based web terminal, and git-backed version history — all without a database or vendor lock-in. Cabinet operationalizes Andrej Karpathy's LLM-wiki pattern as a product, positioning itself as the persistent memory layer for both human and AI work in a self-hosted startup OS.

[[skills.sh]] covers the open agent skills directory and ecosystem built by Vercel, which provides the de-facto distribution layer for SKILL.md-based capability modules across 50+ AI coding agents. The source captures the leaderboard (community-ranked by anonymous install telemetry), the official skills registry (70+ technology vendors publishing skills directly, including Anthropic, Microsoft, GitHub, OpenAI, Sentry, and Cloudflare), a security audit dashboard, and the full CLI reference for `npx skills` backed by the open-source `vercel-labs/skills` repo. It adds a concrete picture of how procedural knowledge is packaged, discovered, and installed across the multi-agent tooling ecosystem referenced throughout this wiki.

[[canva.com]] documents Canva as an AI-powered visual design platform with a developer layer directly relevant to agentic AI workflows. Its remote MCP server (hosted on [[canva.com]]) exposes design generation, editing, asset management, and export as MCP-compatible tools consumable by Claude, ChatGPT, Codex, Gemini, Cursor, and VS Code agents. The Connect APIs enable external platforms to embed Canva capabilities via REST (autofill brand templates, bulk create, resize, export, comments), and the Apps SDK allows JavaScript plugins to run inside the Canva editor. This source is notable as a concrete example of an established SaaS product opening its design capabilities to AI agents through the Model Context Protocol.

[[njbrake-agent-of-empires]] documents Agent of Empires (AoE), a Rust-based open-source terminal session manager for AI coding agents (1,868 stars, v1.5.0). AoE wraps tmux to run Claude Code, OpenCode, Mistral Vibe, Codex CLI, Gemini CLI, Cursor CLI, Copilot CLI, Pi.dev, Factory Droid, and Hermes in parallel — each in an isolated session with agent-aware status detection, git worktree branch isolation, optional Docker sandboxing, and remote phone access via a browser-based PWA. It represents the session-management and multi-agent coordination layer of the stack: not an LLM framework, but the operational harness that keeps multiple coding agents alive, organized, and reachable across devices.

[[tmux-tmux]] documents the canonical Unix terminal multiplexer — the open-source C project (45,000+ stars, ISC License, latest 3.6a) that underpins a growing category of AI-agent infrastructure in this wiki. tmux's session/window/pane hierarchy, detach-reattach model, and scriptable `capture-pane`/`send-keys` interface are the foundational primitives on which [[njbrake-agent-of-empires]] and [[tmuxai.dev]] are both built. The source captures the full build/install path, architecture overview (client/server socket model, ~50 cmd-*.c command files, OS shims), example configuration, and the ecosystem of plugins and tooling that extends it.

[[tmuxai.dev]] introduces TmuxAI, a Go-based AI terminal assistant (1,790 stars, Apache-2.0, v2.1.4) that runs non-intrusively inside a tmux session. It observes all visible panes for context, communicates through a dedicated Chat Pane, and executes commands in an Exec Pane with user confirmation and risk indicators. Key modes — Observe (default), Prepare (shell-prompt integration for exact completion tracking), and Watch (proactive monitoring) — make it adaptable from interactive assistance to continuous log surveillance. Its Knowledge Base and Skills subsystems (built on the SKILL.md pattern also seen in [[skills.sh]]) allow persistent domain context to be injected into every AI interaction, making TmuxAI a practical ambient AI layer for terminal-heavy workflows built on [[tmux-tmux]].

[[shareai-lab-learn-claude-code]] is a 12-session open-source curriculum (58,143 stars, MIT) that reverse-engineers Claude Code by building its full architecture from scratch in Python, one harness mechanism per session. Its central thesis — agency comes from model training, not from orchestration code; harness engineers build the environment the intelligence inhabits — is the clearest articulation of *harness engineering* in this wiki. The curriculum covers the fundamental agent loop (s01), tool dispatch (s02), in-memory planning (s03), subagent isolation (s04), on-demand SKILL.md loading (s05, the same two-layer pattern used in [[skills.sh]] and [[tmuxai.dev]]), context compression (s06), a file-based task graph with `blockedBy` dependency edges (s07), background task threads (s08), persistent agent teams with JSONL mailboxes (s09), team protocols (s10), autonomous task self-claiming (s11), and git-worktree isolation (s12). The repo also ships a companion Next.js platform with interactive diagrams and a sister repo (`claw0`) covering the always-on heartbeat/cron harness variant.

[[anthropics-skills]] is Anthropic's official reference repository for the Agent Skills pattern — 17 SKILL.md-based capability modules for Claude spanning document processing (xlsx, docx, pptx, pdf), creative design, MCP server generation, web testing, and a meta `skill-creator` skill for building and evaluating new skills. With 132,000+ stars it is the most-starred skills repository in the ecosystem and the canonical starting point for anyone writing skills for Claude Code, Claude.ai, or the Claude API. The document skills (`xlsx`, `docx`, `pptx`, `pdf`) are the same skills that power Claude's native document capabilities in Claude.ai (source-available). The `skill-creator` skill demonstrates the on-demand SKILL.md loading pattern also covered in [[shareai-lab-learn-claude-code]] (s05) and distributed through [[skills.sh]].

[[forrestchang-andrej-karpathy-skills]] distills Andrej Karpathy's public critique of LLM coding assistants into four actionable behavioral principles — Think Before Coding, Simplicity First, Surgical Changes, and Goal-Driven Execution — packaged as a single `CLAUDE.md` file and a Claude Code plugin skill (124,694 stars, MIT). It is the community's canonical answer to the failure modes Karpathy identified: silent wrong assumptions, bloated abstractions, untargeted edits, and vague success criteria. The repository connects to [[anthropics-skills]] and [[skills.sh]] through the Claude Code plugin marketplace, and its philosophical core — that agent behavior is shaped by environment and instructions — runs through [[shareai-lab-learn-claude-code]]'s harness engineering curriculum.

[[x.com-mnilax-karpathys-4-claude-md-rules-cut-claude-mistakes]] captures an empirical study by Mnimiy (@mnilax) extending [[forrestchang-andrej-karpathy-skills]]'s 4-rule template with 8 additional rules grounded in 6 weeks of testing across 30 codebases. The 4 original rules cut the mistake rate from ~41% to ~11%; the full 12-rule template brings it to ~3% while preserving ~76% compliance. The 8 new rules address failure modes specific to May 2026 Claude Code workflows that the original January 2026 template did not anticipate: nondeterministic routing logic that should be plain code (Rule 5), context drift from uncapped token usage (Rule 6), incoherent "average" code when codebase patterns conflict (Rule 7), duplicate implementations from writing without reading (Rule 8), hollow test suites that assert output without encoding intent (Rule 9), compounding errors in multi-step tasks without checkpoints (Rule 10), pattern fragmentation from silent convention violations (Rule 11), and silent partial successes masquerading as completions (Rule 12). The article provides the full 12-rule CLAUDE.md template verbatim and a one-command install path that appends to an existing CLAUDE.md.

[[6eanut-llm-wiki]] is a Claude Code skill that implements Andrej Karpathy's LLM Wiki pattern as a fully automated, self-contained knowledge base (35 stars, MIT). It compiles knowledge once from user-supplied source documents into a persistent, interlinked markdown wiki, and keeps it current via SHA-256 incremental caching and session lifecycle hooks — answering questions by reading an auto-generated `index.md` first (O(1) lookup), then 3–5 relevant pages. The skill ships six slash commands (`/wiki-ingest`, `/wiki-query`, `/wiki-lint`, `/wiki-save`, `/wiki-graph`, `/wiki-review`), a two-phase ingest workflow with a human review checkpoint, D3.js knowledge graph generation, bilingual CJK support, and deterministic bash utilities for hashing, orphan detection, and frontmatter validation. Its `CLAUDE.md` / `WIKI.md` template enforces proactive wiki checks without explicit command invocation — the same behavioral pattern advocated by [[forrestchang-andrej-karpathy-skills]] and operationalized in [[runcabinet.com]]. The skill connects to [[anthropics-skills]] and [[skills.sh]] through the Claude Code plugin/skills ecosystem, and its harness architecture — LLM for content, bash for determinism — mirrors the design principles articulated in [[shareai-lab-learn-claude-code]].

[[meetclaras.com]] introduces Claras, an AI-powered YouTube transcript and knowledge-extraction tool that turns any YouTube video into an interactive knowledge base. Delivered as a Chrome extension and web app, Claras retrieves the full transcript of any YouTube video and layers AI Q&A, auto-generated summaries with chapter tables of contents, searchable highlights, and multi-format export (TXT, SRT, PDF, VTT) on top. Its key differentiator for agentic workflows is the export-to-agent pipeline: users can feed full transcripts into Claude, ChatGPT, or custom agents to build research assistants and content analyzers from YouTube video content — useful for ingesting conference talks, product demos, and tutorial libraries into agent knowledge bases. [[reseek.net]] introduces Reseek, a cloud-hosted personal knowledge management platform ("second brain") that saves links, notes, images, PDFs, YouTube videos, and Twitter/X posts into one AI-queryable library. OCR, automatic tagging, semantic search, and AI chat are applied across all content types. What makes it directly relevant to agentic AI stacks is the MCP Server: four tools (`search-library`, `get-library-item`, `save-note`, `save-link`) let LLM clients treat the Reseek library as a structured knowledge backend — an agent can save research during one session and retrieve it semantically in another. [[nidhinjs-prompt-master]] introduces Prompt Master, a Claude skill (SKILL.md-based, v1.6.0, 7,412 stars, MIT) that functions as an on-demand prompt engineer across 30+ AI tools. It silently extracts nine dimensions of intent from a user's rough idea, routes to one of 12 prompt templates, applies five safe techniques (role assignment, few-shot, XML tags, grounding anchors, chain of thought), audits for token waste, and delivers one production-ready copyable prompt. Tool-specific routing handles the behavioral differences between reasoning LLMs (Claude, GPT-5.x, Gemini), thinking LLMs (o3/o4-mini — no CoT added), coding agents (Claude Code, Cursor — stop conditions and file scope required), image AI (Midjourney, Stable Diffusion — comma-separated descriptors and negative prompts), and workflow automation (Zapier, n8n). The skill connects to [[anthropics-skills]] and [[skills.sh]] as another high-star SKILL.md module in the Claude skills ecosystem, and its focus on precise intent extraction and token efficiency complements the behavioral guidelines documented in [[forrestchang-andrej-karpathy-skills]].

[[9d5bzxVsocw-anthropic-just-dropped-the-new-blueprint]] is a 17-minute breakdown by The AI Automators of Anthropic's March 2026 engineering article on harness design for long-running autonomous agents. The video identifies two core failure modes Anthropic observed in practice — context anxiety (models changing behavior as context fills, rushing toward premature completion) and poor self-evaluation (agents approving their own mediocre work) — and walks through the three-agent architecture built to address them: a planner (expands a terse prompt into a structured spec), a generator (builds the work), and an evaluator (judges it adversarially, inspired by GAN discriminator architecture). Two real case studies illustrate the evolution: a 2D retro game maker built with Opus 4.5 using sprint-based context resets and per-sprint contract negotiation, and a browser-based digital audio workstation built with Opus 4.6 in a single continuous 4-hour, $125 session relying entirely on context compaction. The key takeaway — that every harness component encodes an assumption about model incapability, and those assumptions go stale as models improve — connects directly to the harness engineering curriculum in [[shareai-lab-learn-claude-code]] and the orchestration patterns in [[langchain.com-langgraph]] and [[njbrake-agent-of-empires]].

[[anthropic.com]] captures Anthropic's developer platform and original harness research. The umbrella source ties together [[anthropic.com-messages]] (direct Messages API for custom agent loops and Agent Skills) and [[anthropic.com-managed-agents]] (pre-built managed agent harness for long-running autonomous tasks). The engineering article that anchors the ingest introduces a three-agent GAN-inspired architecture — planner, generator, evaluator — built on top of the Claude Agent SDK and Managed Agents infrastructure, with documented experiments building a retro game maker (6 hr, $200, Opus 4.5) and a browser-based DAW (3 hr 50 min, $125, Opus 4.6).

[[anthropic.com-messages]] documents the Messages API: direct model access for custom agent loops, tool use, function calling, extended thinking, batch processing, and the Agent Skills system. Agent Skills use three-tier progressive disclosure (metadata → instructions → bundled scripts) to inject modular capability into Claude sessions without context overhead. This is the same Agent Skills pattern documented in depth in [[anthropics-skills]] and distributed through [[skills.sh]].

[[anthropic.com-managed-agents]] documents Claude Managed Agents: a fully managed agentic harness with secure cloud containers, automatic context compaction, server-side session persistence, and multi-agent thread orchestration. Detailed harness engineering findings from Anthropic's own experiments are documented here — including the two primary failure modes (context anxiety and poor self-evaluation), the planner-generator-evaluator architecture, sprint contracts, and the evolution principle: every harness component encodes an assumption about model incapability, and those assumptions go stale as models improve. The same content is covered in video form in [[9d5bzxVsocw-anthropic-just-dropped-the-new-blueprint]].

[[gsd-build-get-shit-done]] introduces GSD (Get Shit Done), a lightweight meta-prompting, context engineering, and spec-driven development system for AI coding agents (62,040 stars, MIT, JavaScript/TypeScript). GSD's central innovation is solving *context rot* — the quality degradation that accumulates as an agent's context window fills — by keeping the orchestrating session at 30–40% utilization while delegating all heavy work to fresh 200k-token subagent contexts. The six-command loop (new-project → discuss → plan → execute → verify → ship) produces persistent structured artifacts (`.planning/` Markdown + JSON) that survive session resets. Its v1.40 two-stage hierarchical routing reduces per-turn skill-listing cost from ~2,150 to ~120 tokens. GSD complements [[obra-superpowers]] and shares the multi-agent subagent-orchestration pattern with [[shareai-lab-learn-claude-code]] and [[anthropic.com-managed-agents]].

[[obra-superpowers]] is a complete software development methodology for AI coding agents built on 14 auto-triggering composable SKILL.md skills (190,063 stars, MIT, v5.1.0). Its distinguishing characteristic is the `using-superpowers` bootstrap skill that loads at session start and mandates skill invocation before any agent response — even with a 1% chance of applicability. The methodology is opinionated: spec before code (brainstorming), git worktree isolation, subagent-per-task with two-stage review, strict RED-GREEN-REFACTOR TDD, and human-in-the-loop checkpoints at every transition. It is a zero-dependency plugin available on the official Claude plugin marketplace and six other harnesses. Superpowers shares the SKILL.md pattern with [[anthropics-skills]] and [[skills.sh]], and the subagent orchestration approach with [[gsd-build-get-shit-done]] — the two projects are the dominant choices for teams seeking a disciplined AI coding methodology.

[[coleam00-archon]] introduces Archon, the first open-source harness builder for AI coding (21,422 stars, MIT, TypeScript, v0.3.11). Where [[obra-superpowers]] and [[gsd-build-get-shit-done]] encode the *methodology* of AI-assisted development as composable skills, Archon encodes the *workflow structure* as committed YAML DAGs. Each workflow is a directed acyclic graph of nodes — AI prompt steps, bash commands, loop-until conditions, and human approval gates — that the Archon engine executes in isolated git worktrees so five tasks can run in parallel with no branch conflicts. The 17 built-in workflows (`archon-fix-github-issue`, `archon-idea-to-pr`, `archon-comprehensive-pr-review` with five parallel reviewers, `archon-refactor-safely`, and others) cover the full development lifecycle. Platform adapters for CLI, Web UI, Slack, Telegram, GitHub, and Discord route into a single orchestrator backed by SQLite or PostgreSQL; the web dashboard unifies all conversations regardless of entry point. This positions Archon as the infrastructure layer that addresses the same nondeterminism problem [[anthropic.com-managed-agents]] identifies — but from a self-hosted, YAML-first, multi-provider angle (Claude Code SDK, Codex SDK, Pi), committed directly to the repo so the whole team runs the same process.

[[gastownhall-beads]] introduces Beads (`bd`), a distributed graph-based issue tracker designed as a persistent memory upgrade for AI coding agents (23,795 stars, MIT, Go, v1.0.4). Where [[gsd-build-get-shit-done]] solves context rot at the session level through fresh-context subagent delegation, and [[coleam00-archon]] structures workflow execution as committed YAML DAGs, Beads addresses the deeper persistence problem: agents have no durable task memory between sessions, and resort to markdown TODO files that accumulate noise and lose dependency structure. Beads replaces those files with a Dolt-powered SQL database (`bd-a1b2`-style hash IDs, full dependency graph, `bd ready` for surfacing unblocked work, `bd prime` for injecting workflow context at session start) that persists across sessions, branches, and concurrent agents without collision. Integration recipes (`bd setup claude`, `bd setup copilot`, `bd setup codex`, and more) install hooks and instruction snippets for 10+ AI coding environments, and the minimal/full profile split keeps hook-enabled agents pointed at `bd prime` as the single source of truth while AGENTS-first agents receive the full command reference inline.

[[huggingface.co]] is the open-source AI platform where the machine learning community collaborates on models, datasets, and applications — hosting 2M+ models, 1.5M+ datasets, and 1.5M+ Spaces. For agentic AI practitioners it matters on two levels: as the primary distribution layer for open-weight foundation models (Llama, Mistral, Qwen, and thousands more) used across agent frameworks including [[langchain.com]] and smolagents alike, and as the home of smolagents — a ~1,000-line Python library for code-first agents (`CodeAgent` writes tool calls as executable Python; `ToolCallingAgent` covers JSON-based tool calling) that is model-agnostic, MCP-compatible, and integrated with the Hub for publishing and loading tools. The platform's Transformers library is the ecosystem pivot: model definitions supported there are compatible with training frameworks (Axolotl, Unsloth, DeepSpeed), inference engines (vLLM, SGLang, TGI), and post-training libraries (TRL, PEFT, Accelerate) — making Hugging Face the connective tissue between open-weight research and production agent deployment.

[[pytorch.org]] documents PyTorch, the dominant open-source deep learning framework (~100k GitHub stars, v2.12.0, BSD-style license, Linux Foundation). PyTorch provides GPU-accelerated tensor computation and a dynamic tape-based autograd system, making it the foundational infrastructure for virtually all modern LLM and vision model training and fine-tuning. For agentic AI practitioners, PyTorch matters as the runtime substrate: the models served by [[huggingface.co]], the inference engines powering agent backends, and the research prototypes that become production systems are almost universally built on PyTorch. Key capabilities covered: eager execution with TorchScript compilation for production, TorchServe for scalable model serving, `torch.distributed` for multi-GPU/multi-node training, the `torch.compile` stack (TorchDynamo + TorchInductor) for automatic kernel optimization, ExecuTorch for edge/mobile deployment, and a rich ecosystem of domain libraries (TorchVision, TorchText, TorchAudio) and third-party tools (vLLM, DeepSpeed, PyTorch Geometric).

[[litellm.ai]] introduces LiteLLM, an open-source AI Gateway (Y Combinator W23, 47k+ GitHub stars) that gives teams a single OpenAI-compatible interface to 100+ LLM providers — OpenAI, Anthropic, Bedrock, Gemini, Azure, Vertex AI, HuggingFace, VLLM, and NVIDIA NIM among them. It is used both as a Python SDK (`completion()` with consistent output format regardless of provider) and as a self-hosted Proxy Server for centralized access control, spend tracking, load balancing, and guardrails across an organization. The proxy accepts any OpenAI-format client without code changes and also serves as a unified gateway for A2A agents (LangGraph, Vertex AI Agent Engine, Bedrock AgentCore, Pydantic AI) and MCP tools. Key capabilities: multiple routing strategies (weighted pick, latency-based, rate-limit-aware, lowest-cost), traffic mirroring for silent A/B experiments, PostgreSQL-backed virtual keys with per-key budget and RPM/TPM limits, automatic spend tracking via a stored model cost map, and pre/post-call guardrails via Aporia, Lakera, Presidio, or a generic webhook API. Observability integrates via a single `success_callback` line covering Langfuse, MLflow, Helicone, and 20+ others. Adopted by Stripe, Netflix, Google ADK, and OpenHands, LiteLLM fills the provider-abstraction and gateway layer that frameworks like [[langchain.com]] and [[huggingface.co]] smolagents rely on for multi-provider routing in production.

[[openrouter.ai]] introduces OpenRouter, a hosted API gateway that gives developers and agentic applications unified access to 400+ AI models from 60+ providers through a single OpenAI-compatible endpoint. Where [[litellm.ai]] is a self-hosted open-source proxy, OpenRouter is a managed SaaS layer that handles provider routing, automatic failover, uptime monitoring, and cost optimization transparently. Its default routing strategy uses price-based load balancing weighted by inverse square of cost, with automatic fallback when a provider degrades — making it a practical reliability layer for teams that don't want to manage individual provider accounts. Beyond a raw HTTP API, OpenRouter offers typed Client SDKs (TypeScript, Python, Go) and an Agent SDK (`@openrouter/agent`) with built-in `callModel` loops, Zod-typed tool definitions, and composable stop conditions (`stepCountIs`, `maxCost`), removing the need to write custom agentic loop infrastructure. Enterprise features include Zero Data Retention endpoints, EU in-region routing, and fine-grained data-collection policies. With 8M+ global users and 250k+ apps integrated, OpenRouter has become a de facto model-access tier for platforms like Replit and Hermes Agent.

[[zilliztech-claude-context]] introduces Claude Context, a Milvus/Zilliz-backed MCP plugin (11,432 stars, MIT, TypeScript) that adds semantic code search to Claude Code and other MCP-compatible AI coding agents. Rather than loading entire directories into the context window on every request — expensive and often infeasible for large codebases — Claude Context indexes the codebase once into a Zilliz Cloud vector database and exposes four MCP tools (`index_codebase`, `search_code`, `get_indexing_status`, `clear_index`) that pull only the semantically relevant code chunks into the agent's context on demand. Indexing is asynchronous; the agent can search partial results immediately while background indexing continues. The plugin supports multiple embedding providers (OpenAI by default, plus VoyageAI, Gemini, and Ollama for fully local deployments) and ships as three separate npm packages — a core library, the MCP server, and a VS Code extension. It is a concrete, narrowly-scoped MCP tool in contrast to the reasoning-layer MCP servers covered by [[sequentialthinking-mcp]].

[[github-spec-kit]] introduces Spec Kit, GitHub's open-source toolkit for Spec-Driven Development (SDD) — a methodology where specifications become executable artifacts that drive AI-powered implementation rather than serving as disposable scaffolding. With 102k+ stars and support for 30+ AI coding agents, it is the most prominent structured-workflow toolkit in the ecosystem. The `specify` CLI bootstraps any project directory with template files and agent integrations (Claude Code, Copilot, Gemini, Codex, Cursor, and more), then exposes a staged pipeline of slash commands — `/speckit.constitution` → `/speckit.specify` → `/speckit.clarify` → `/speckit.checklist` → `/speckit.plan` → `/speckit.analyze` → `/speckit.tasks` → `/speckit.implement` — each producing a committed artifact the agent references in the next step. Extensions add new capabilities; presets customise how the core behaves (from Agile framing to full regulatory traceability). It occupies a complementary position to [[gsd-build-get-shit-done]] (which focuses on context-rot management and subagent orchestration) and to [[anthropics-skills]] and [[obra-superpowers]] (which package capabilities rather than workflow stages).

[[openspec.dev]] introduces OpenSpec, a lightweight open-source spec-driven development (SDD) framework by Fission (49k+ stars, MIT, TypeScript, v1.3.1) that natively supports 25+ AI coding agents including Claude Code, Cursor, Codex, GitHub Copilot, and Windsurf — no API keys, no MCP required. Its core pattern: specs live as structured Markdown in `openspec/specs/`, each proposed change gets its own folder in `openspec/changes/` with `proposal.md`, `design.md`, `tasks.md`, and delta specs capturing ADDED/MODIFIED/REMOVED requirements. The artifact-guided workflow — `/opsx:propose → /opsx:apply → /opsx:archive` — aligns human and AI on requirements before any code is written, and archived changes merge deltas into the source-of-truth spec library. OpenSpec is explicitly brownfield-first (most tools assume greenfield) and positions itself as a lighter alternative to [[github-spec-kit]] (rigid phase gates, Python-based) and Kiro (IDE-locked). Community schemas extend the base workflow in a pattern similar to how [[skills.sh]] distributes SKILL.md modules. The companion GitHub repo (Fission-AI/OpenSpec) holds all documentation and is itself developed spec-driven, dogfooding the pattern.

[[the-new-sdlc-with-vibe-coding]] is the foundational whitepaper for this wiki's entire domain, authored by Addy Osmani, Shubham Saboo, and Sokratis Kartakis (May 2026, Google Agents Whitepaper Series, Day 2). It defines the spectrum from casual vibe coding to disciplined agentic engineering across six dimensions (intent specification, verification, codebase understanding, error handling, scope, and risk profile), and argues that the single sharpest discriminator is systematic verification — tests for deterministic behavior plus evals for non-deterministic trajectories. It names and frames three major mental models: the **spectrum** (vibe coding → structured AI-assisted → agentic engineering), the **harness** (Agent = Model + Harness, with six components: rule files, tools, sandboxes, orchestration, hooks/guardrails, observability), and the **factory model** (the developer's primary output is the system that builds software, not code itself). The harness effect is empirically grounded: a single benchmark team moved from outside the Top 30 to Top 5 on Terminal Bench 2.0 by changing only harness configuration with no model change. The paper also names the **80% problem** (AI rapidly generates ~80% of code; the remaining 20% requires deep contextual knowledge and is where dangerous conceptual failures hide), the **conductor vs. orchestrator** developer role duality, and the **context engineering** discipline with six context types (Instructions, Knowledge, Memory, Examples, Tools, Guardrails) and the static/dynamic split. Economically, it reframes AI development around CapEx/OpEx: vibe coding has near-zero upfront cost but hides compounding OpEx (token burn, maintenance tax, security remediation), while agentic engineering inverts this with higher upfront CapEx yielding dramatically lower marginal OpEx per feature shipped. It closes with actionable starting points for individual developers (write AGENTS.md first, write tests before code, review every line that ships), engineering leaders (eval suites as a production gate, AI-specific code review training, harness as shared team infrastructure), and organizations (build the production substrate before scale, adopt MCP and A2A as open standards, reframe hiring around judgment and specification rather than implementation velocity).

[[kepano-obsidian-skills]] is Steph Ango's official Agent Skills pack for Obsidian (39k+ stars, MIT) — five SKILL.md modules that teach coding agents to work with Obsidian Flavored Markdown (wikilinks, embeds, callouts, properties), Bases (`.base` database views), JSON Canvas (`.canvas` spatial layouts), the Obsidian CLI (vault read/create/search, plugin development cycle), and Defuddle (clean web-page markdown extraction). Installable via Claude Code marketplace (`obsidian@obsidian-skills`), `npx skills add`, or manual copy into agent skills directories. It is the canonical reference for agents operating inside Obsidian vaults — the PKM layer that [[runcabinet.com]] and [[6eanut-llm-wiki]] both build on — and connects to the broader skills ecosystem via [[skills.sh]], [[anthropics-skills]], and [[voltagent-awesome-agent-skills]]. The `obsidian-cli` skill's plugin-reload → error-check → screenshot workflow is a concrete example of agent-assisted Obsidian plugin development.
