OpenAI's official Claude Code plugin that bridges the Codex CLI into Claude Code, enabling developers to trigger Codex code reviews and delegate background tasks without leaving their Claude Code session. With 19k+ stars it is the most widely adopted cross-agent workflow bridge in the Claude Code ecosystem to date.

_All claims below are sourced from ../../raw/github/openai-codex-plugin-cc.md unless otherwise noted._

## What it does

The plugin exposes a suite of slash commands (`/codex:review`, `/codex:adversarial-review`, `/codex:rescue`, `/codex:status`, `/codex:result`, `/codex:cancel`, `/codex:setup`) and a `codex:codex-rescue` subagent directly inside Claude Code. It delegates all execution to the locally installed Codex CLI and Codex app server — the plugin itself adds no separate runtime or auth; it reuses the developer's existing Codex install and credentials.

## Key features

- **`/codex:review`** — read-only code review of uncommitted changes or a branch diff (`--base <ref>`); supports `--background` and `--wait` for long-running multi-file reviews.
- **`/codex:adversarial-review`** — steerable review that challenges design choices, tradeoffs, hidden assumptions, and failure modes; accepts free-text focus instructions after the flags.
- **`/codex:rescue`** — hands an arbitrary task (bug investigation, fix, continuation) to the `codex:codex-rescue` subagent; supports `--resume`, `--fresh`, `--model`, and `--effort` to control which Codex model and reasoning level are used.
- **`/codex:status` / `/codex:result` / `/codex:cancel`** — manage background Codex jobs per-repo; result output includes the Codex session ID for direct `codex resume` in the Codex app.
- **Review gate** — an optional `Stop` hook (`/codex:setup --enable-review-gate`) that runs a targeted Codex review on every Claude response before allowing Claude to stop; blocks the stop if issues are found. High usage-limit risk — intended for supervised sessions.
- **Model and effort overrides** — per-project `.codex/config.toml` sets `model` and `model_reasoning_effort`; user-level `~/.codex/config.toml` provides defaults; project config loads only when the project is trusted.

## Architecture

The plugin is a Claude Code plugin package (`@openai/codex-plugin-cc`) structured under `plugins/codex/` with standard subdirectories: `commands/` (slash command handlers), `agents/` (the `codex-rescue` subagent definition), `hooks/` (Stop hook for review gate), `prompts/`, `schemas/`, `scripts/`, and `skills/`. The marketplace manifest lives in `.claude-plugin/marketplace.json` and is registered via `/plugin marketplace add openai/codex-plugin-cc` then installed with `/plugin install codex@openai-codex`. All command execution is dispatched through the global `codex` binary, making the plugin a thin orchestration layer over the Codex app server API (`codex app-server`). TypeScript source is compiled with `tsc` targeting the app-server types generated by `codex app-server generate-ts`.

## Installation

```bash
# Add marketplace, install plugin, reload
/plugin marketplace add openai/codex-plugin-cc
/plugin install codex@openai-codex
/reload-plugins

# Check Codex is installed and authenticated
/codex:setup
```

If Codex CLI is not yet installed: `npm install -g @openai/codex`. If not logged in: `!codex login` (supports ChatGPT account or API key). Requires Node.js ≥ 18.18.

## Example usage

```bash
# Quick review of uncommitted changes
/codex:review

# Branch review before merge
/codex:review --base main

# Adversarial review focused on a risk area
/codex:adversarial-review --background look for race conditions and question the retry design

# Delegate a bug investigation to Codex
/codex:rescue investigate why the tests started failing

# Check on background work
/codex:status
/codex:result
```

To resume a Codex task directly in the Codex app:
```bash
codex resume <session-id>   # session-id shown by /codex:result
```
