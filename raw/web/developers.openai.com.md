## Quickstart — https://developers.openai.com/api/docs/guides/agents/quickstart
Install: `npm install @openai/agents zod` or `pip install openai-agents`

Create and run first agent with Agent + run/Runner.run.

State strategies for next turn: full history in app, SDK session, OpenAI conversationId, previous_response_id.

Add function tools with zod/function_tool decorators.

Add specialist agents with handoffs (triage → history/math tutors).

Inspect traces in Traces dashboard early.


## Agent definitions — https://developers.openai.com/api/docs/guides/agents/define-agents
Agent packages model, instructions, tools, guardrails, MCP, handoffs, structured outputs.

Properties: name, instructions, prompt, model, tools, handoff_description, handoffs, outputType/output_type, guardrails, MCP servers.

Local context (RunContext) separate from model context — pass user info, DB clients without sending to model.

Split agents when different tool surfaces, approval policies, models, or trace legibility needed.


## Running agents — https://developers.openai.com/api/docs/guides/agents/running-agents
Agent loop: call model → inspect output → execute tools → handoffs → final answer.

Conversation strategies:
| Strategy | Where state lives |
| toInputList/history | Your application |
| session | Your storage + SDK (MemorySession, SQLiteSession) |
| conversationId | OpenAI Conversations API |
| previous_response_id | OpenAI Responses API |

Streaming: same loop, consume events; wait for completion; resume from state on approval/cancel.

Treat approvals as paused runs, not new turns.


## Orchestration and handoffs — https://developers.openai.com/api/docs/guides/agents/orchestration
Patterns:
| Handoffs | Specialist owns next response |
| Agents as tools | Manager stays in control, calls specialists as bounded capabilities |

Handoffs: Agent.create with handoffs array, handoff() wrapper for advanced config.

Agents as tools: specialist.asTool({ toolName, toolDescription }).

Add specialists only when contract materially changes.


## Guardrails and human review — https://developers.openai.com/api/docs/guides/agents/guardrails-approvals
Guardrails: input (block before main model), output (validate before leaving system), tool (around function calls).

Human review: needsApproval on tools; run pauses with interruptions + resumable state; approve/reject then run(agent, state).

Agent-level guardrails: input only first agent, output only final agent, tool guardrails per function tool.

Streaming uses same interruption/state model.
